# Waterfall Tools Implementation Plan

This document breaks down the development of the Waterfall Tools library into independent, bite-sized tasks suitable for an AI agent to tackle sequentially. We are adopting a **Bottom-Up, CLI-First** approach. By building standalone input processors first, we establish robust, known-good data fixtures that downstream UI and rendering systems can rely on immediately.

## Phase 1: Core Setup & Schema Definition

- [x] Initialize the Node project configuration with Rollup/Vite.
- [x] Create the directory structure outlined in `Docs/Architecture.md`.

- [x] Add decoding, processing, and validation for tcpdump formats (`src/inputs/tcpdump.js`), executed in the following sub-steps:
  *(Note: The underlying binary streamer `PcapParser` processes `Uint8Array` chunks natively. PCAPNG support is implemented based on the spec but contains TODOs marking missing IDB timestamp mappings pending `pcapng` file-based tests. The parser itself handles initial structural decoding out to `Ethernet, IPv4/6, TCP, UDP` fields.)*

  - [x] **TLS Key Log Loading:** Load the TLS key log that matches the given tcpdump capture file (or extract embedded key logs from cap file bundles).
    *(Note: Sample key logs are located in `Sample/Data/tcpdump/` alongside the PCAPs. The key log files have the exact same base file name as their corresponding `.cap.gz` captures, but end in `.key_log.txt.gz`.)*
  - [x] **TCP Stream Reconstruction:** Build raw data streams for TCP (with timestamps for each segment) based on src/dest IP/port and SYN/FIN packets. Handle retransmits, overlapping windows, and out-of-order packets.
  - [x] **UDP Stream Reconstruction:** Build virtual connection "streams" for UDP based on packet numbers and src/dest IP/ports.
  - [x] **TCP TLS Decryption:** Decrypt TLS-encrypted TCP streams using the key log, keeping per-chunk timestamps that match packet timings. (Reference RFC specs or utilize/build stand-alone utility libraries for TLS decoding).
  - [x] **TCP Protocol Decoding:** Detect and decode HTTP/1.x, HTTP/2, and DNS over HTTP from unencrypted TCP streams into extractable individual requests (including connection setup and affinity info).
  - [x] **UDP Protocol Detection & QUIC Decryption:** Detect DNS and QUIC formats on UDP. For TLS-encrypted QUIC, decrypt the stream using the keylog.
  - [x] **DNS Decoding:** Decode DNS traffic (from both UDP and TCP/DoH) and store the lookups to add to request timings.
  - [x] **QUIC Decoding:** Decode unencrypted QUIC traffic to extract streams and parse the relevant requests.
  - [x] **Page Entry Creation:** Create a virtual "page" entry. Use the first HTTP request with `Sec-Fetch-Dest: document` as the page URL, defaulting to the first HTTP request if none is found.
  - [x] **HAR Generation & Validation:** Turn the decoded protocols from the tcpdump processing into requests and page data that can be used for generating the HAR format and then the creation and validation of the resulting HAR from the tcpdump input.
- [x] Restructure the `src/inputs` directory so that the core libraries are separated from the cli interfaces and utility functions (in a logical grouping in separate folders) so it's not a flat, giant collection of files. If it makes sense, the core libraries can be at the root.
- [x] **Zero Polyfill Migration:** Convert all node-native stream and crypto logic globally across all input pipelines to purely Web APIs native to Browser engines to ensure a fundamentally lightweight and robust isomorphic library footprint.
- [x] Integrate fallback mapping engine for missing `URL_REQUEST_START_JOB` data from `v8.timeline` categories natively mapping `requestTime` fallbacks.
- [x] Address catastrophic C++ memory address pointer overlapping within `devtools.netlog` array processing inside `chrome-trace`.
- [x] Normalize `CLOCK_MONOTONIC` system uptimes within Chrome Traces to real UNIX epochs dynamically extracting `date:` HTTP response headers preventing 1970 Date object regressions across renderer timeouts.
- [x] Enforce universal monotonic bound isolation handling negative Chrome Trace cache hydration properties smoothly guaranteeing absolute metric spans logically tracking `start <= first_byte <= end` organically.
- [x] Make every standalone per-format CLI wrapper emit true Extended HAR (`{ log: {...} }`): extract `WaterfallTools.getPage()`/`getHar()` verbatim into raw-Node-safe `src/core/har-export.js` (`getPageFromData`/`relationalToHar`, only import: `version.js`), delegate the class methods to it, and route all `src/inputs/cli/*` wrappers through `relationalToHar(data)` instead of serializing the internal relational object. ## Phase 8f: CORS Fetch Proxy (Cloudflare Worker)
**Goal:** Provide a deploy-ready, self-contained Cloudflare Worker that acts as a CORS-friendly fetch fallback for URL-based imports when remote origins do not send `Access-Control-Allow-Origin` headers — without becoming an open proxy.
- [x] Create the `cloudflare-worker/` top-level directory containing `worker.js` (single-file module Worker), a minimal `wrangler.toml`, and a deployment `README.md`.
- [x] Gate all Worker logic behind `url.pathname === '/fetch'`; every other path passes through unmodified via `fetch(request)`.
- [x] Parse the `url` query parameter, validate it's an absolute `http(s)://` URL, and block obvious SSRF targets (loopback, RFC 1918, link-local, CGNAT, `localhost`/`.local`/`.internal`, IPv4-mapped IPv6) before any upstream fetch.
- [x] Forward the caller's real IP via `X-Forwarded-For` (appending to existing chain), `X-Real-IP`, `Forwarded` (RFC 7239 quoted), and a `Via: 1.1 waterfall-tools-proxy` header so the proxy is intentionally non-anonymizing.
- [x] Read the first 64 KB of the upstream response, run the same format-sniff logic as `src/inputs/orchestrator.js#identifyFormatFromBuffer` (inlined into the Worker so it stays a single file), and reject with `415 unsupported_format` anything that isn't a recognised waterfall-tools input.
- [x] Stream the matched body back to the caller by replaying the buffered sniff chunks (one-per-pull for backpressure) followed by unmodified pass-through of the remaining `reader.read()` output. No reassembly, no content transformation; `Content-Encoding` / `Content-Type` / `Content-Length` / `ETag` / `Last-Modified` / `Cache-Control` are copied verbatim.
- [x] Add `Access-Control-Allow-Origin: *` (and `Access-Control-Expose-Headers` for the format label) so anonymous-mode `fetch()` works against the proxy.
- [x] Implement per-IP failure rate limiting using an in-memory `Map<string, {count, firstFailureMs}>` keyed by `CF-Connecting-IP` (default 10 failures per 10 minutes → 429 until the window rolls over), with a map-size cap (default 10 000 entries). When the cap is reached and every tracked entry is still within its active window, refuse to evict (preventing unique-IP flood attacks from silently rolling real offenders off the FIFO) and **fail-closed**: reject all `/fetch` requests with 429 until the oldest tracked entry ages out.
- [x] Reject `HEAD` on `/fetch` because there's no body to sniff; handle `OPTIONS` preflights with the appropriate CORS headers.
- [x] Enforce an upstream fetch timeout via `AbortController` and a Content-Length cap to keep Worker CPU/memory bounded.
- [x] Document the lockstep sync requirement: every new input format added to the orchestrator MUST also be added to the Worker's sniff logic (`AGENTS.md` §76, `cloudflare-worker/README.md`).

## Phase 12: qlog (QUIC/HTTP-3) Input Support — beta
**Goal:** Import [qlog](https://quicwg.org/) structured QUIC/HTTP-3 logs (main-schema / quic-events / h3-events drafts) as a first-class input format. ### Design decisions (from planning review, 2026-07-05)
- **File injection = postMessage embed API (fork patch), not URL params.** qvis has no programmatic loading API today; its URL-param forms either load a single file client-side (`?file=`) or, for multiple files (`?file1=&file2=…`), fall back to a qvis-server backend `/loadfiles` endpoint we will not host (`ConnectionStore.ts:177-226`). Since the waterfall viewer's multi-file qlog drops must reach qvis, the fork adds a small embed shim: qvis posts `{type:'qvis-ready'}` to `window.parent` after mount; the parent replies `{type:'qvis-load-files', files:[{name, data:ArrayBuffer}]}`; the shim wraps each member as a `File` and routes it through the existing `FileLoader`/`ConnectionStore` path (which already accepts `File` objects — the same code the local-file picker uses). Origin-checked both ways (same-origin embedding). Generic enough to upstream to `quiclog/qvis` as an "embed mode".
- **Fork is fully modernized (maintainer decision, revised 2026-07-05): Vite 8 + Vue 3 + TypeScript 5 on Node 22 — we own this fork permanently, so no EOL framework in the final state.** The earlier Vue 2.7 bridge was scoped for a low-divergence fork; with the decision to fully maintain our own fork, staying on Vue 2 (EOL Dec 2023) just defers the rewrite while accruing risk. Target stack, verified against npm 2026-07-05: Vite `^8` with `@vitejs/plugin-vue@^6` (peer range includes Vite 8 — matches the main repo's Vite), TS 5.x with decorators **removed entirely** (class-component/`vue-property-decorator` components rewritten to Composition API `<script setup lang="ts">`; plain Options API acceptable for trivial components), Vuex + `vuex-module-decorators` stores → **Pinia** (`ConnectionStore`/`ConfigurationStore` map naturally), tslint dropped. **bootstrap-vue → plain Bootstrap 5 markup + small local components, NOT BootstrapVueNext:** a usage audit shows ~235 of ~315 `b-*` instances are pure layout/table markup (`b-row`/`b-col`/`b-container`/`b-td`/`b-tr`/`b-th`/`b-table-simple`…) that maps 1:1 onto Bootstrap CSS classes; the behavioral remainder is tiny (2 `b-modal`, 1 `b-tabs` group, ~12 form controls — near-native in Bootstrap 5, e.g. `.form-select` — plus buttons/alerts/nav that are class styling). BootstrapVueNext is still pre-1.0 (`0.45.x`) and drags seven peer dependencies (`reka-ui`, `@vueuse/*`, `focus-trap`, `@floating-ui/vue`, …) — the wrong trade for mostly-static markup. `@vue/compat` may be used as migration scaffolding but must be gone from the final published state. **The D3 renderer classes (the actual visualization logic) are framework-agnostic TS and stay as intact as possible — framework churn moves around them, not through them.** Heavy divergence from `quiclog/qvis` is accepted — modernized code over legacy parity; upstream is low-activity, and the spec-final qlog support can still be offered upstream as a concept/separate PR even if nothing else applies.
- **qlog model/loader correctness is decoupled from the Vue UI migration.** The loader/model layer (`src/data/`) is pure TS with no Vue dependency; the fork gains vitest (same framework as the main project) with UI-independent parser/model tests covering both draft-era and spec-final inputs, so Vue-migration bugs and qlog-spec bugs can never blur together. The UI migration is validated separately by visual smoke tests (sequence / multiplexing / congestion against known files). Because of this split, the spec-final loader work can proceed in parallel with the UI migration.
- **Distribution = optional npm package published from the fork; qvis is opt-in exactly like DevTools, never in the base tarball.** With a Node-22 build there is no reason to commit `dist/` to git: the fork's `visualizations/` gains npm packaging metadata (`files: ["dist"]`, package name **`@pmeenan/qvis`** (originally `qvis`, confirmed unclaimed 2026-07-05, but npm's typosquat guard 403s unscoped `qvis` at publish time — "too similar to `qs`/`is`" — so it was scoped 2026-07-06 with `publishConfig.access: public`)) and publishes its built bundle. waterfall-tools consumes it exactly like `@chrome-devtools/index`: **devDependency** (hosted-site builds + dev serve) + **optional peerDependency** (`peerDependenciesMeta.optional: true`) for embedders. `package.json#files` does NOT include any `dist/browser/qvis-*` path — embedders who skip the package pay zero bytes; those who want it `npm install` it and `install-viewer` picks it up. Absence is first-class everywhere: empty `waterfall-qvis-path` meta → viewer never unhides the tab; `install-viewer` skips quietly; only `scripts/build.js` warns (the repo's own build expects its devDependency). The submodule remains the fork's source workspace, no longer a distribution channel. **Tarball-integrity note:** the published tarball's `index.html` is built with the repo's devDependencies installed, so its meta tags can reference directories excluded from `files` — this is the existing devtools precedent (`install-viewer` is the documented fix-up that rewrites metas for the embedder's tree). qvis follows the same shape, with two hardenings: `install-viewer` sets the qvis meta from the resolved optional package when present and **empties it** when absent (never leaves a dangling path), and the viewer independently verifies `qvisPath + 'index.html'` is actually fetchable before ever unhiding the tab — so even a stale/hand-copied `index.html` degrades to "no qvis tab", never a broken one.
- **Raw qlog bytes retained in core; new `getPageResource(pageId, 'qlog')` route.** Single-buffer qlog loads already retain `_rawBuffer`; multi-buffer `loadBuffers()` deliberately clears it. Add `_rawBuffers` retention (per-member exact ArrayBuffer copies + original file names) for multi-buffer qlog loads so the qvis tab works for merged drops and survives page/tile navigation, mirroring the existing `trace`/`netlog` raw-passthrough routes.
- **Parent decompresses gzip before injection AND normalizes filenames.** Outer-gzipped qlog members are inflated viewer-side (`DecompressionStream`) before postMessage. qvis sniffs content but keys real behavior off extensions, and its extension map knows `.sqlog`/`.qlog` but not `.sqlog.gz` (`FileLoader.ts` `extensionMap`) — so after inflation, strip compression suffixes (`.gz`/`.br`/`.zip`) from the original drop filename, or when the name is unknown/unhelpful synthesize `connection-N.sqlog` / `.qlog` by content sniff (leading `0x1E` → JSON-SEQ). Never hand qvis decompressed bytes under a `*.gz` name.
- **The fork gains first-class spec-final qlog support (maintainer decision) — qvis must ingest the same modern qlog corpus waterfall-tools parses.** `QlogLoaderV2.fromJSON` hard-requires a top-level `qlog_version` and only accepts draft-02-era aliases (`QlogLoaderV2.ts:14-30`); it knows nothing of spec-final quiche logs (no `qlog_version`, self-identified via `file_schema`/`event_schemas` URNs), `quic:`/`http3:` namespace renames (incl. the `recovery:metrics_updated` → `quic:recovery_metrics_updated` move), RawInfo frame lengths (`raw.payload_length`), object-form `reference_time`, or `relative_to_previous_event` clocks — exactly the inputs our own parser was hardened for (mine `src/inputs/utilities/qlog/` and its AGENTS.md rules as the reference implementation). Since divergence is accepted, this is proper loader support (a spec-final loader / schema module in the fork), not a bolt-on normalizer shim. Receiving the files successfully is not the bar; rendering them is — validated against all three sample corpora (`Sample/Data/qlog/aioquic`, `curl`, `quiche` — both vantages).

## Phase 15: qvis Events tab (netlog-style raw event browser)
**Goal:** Add an "Events" tab to the qvis fork, placed before "Sequence" in the nav, that provides a netlog-events-style split-pane browser over the raw qlog event stream: a filterable, virtualized event list on the left and a details + stream-context panel on the right. Fills the "raw event inspection" gap (today every qvis tab is a visualization or aggregate; debugging a capture means opening the `.sqlog` in a text editor). Self-contained and upstreamable to `quiclog/qvis`.

### Design decisions (agreed 2026-07-05)
- **Placement & routing:** new `/events` route + `MainMenu` nav entry inserted before Sequence, with its own active-tab color following the per-tab color pattern. Embedded default route stays `/sequence` (revisit later). **(Amended 2026-07-05, per Pat: the embedded default is now `/events` — the router's `/` redirect and the embedded `/files` guard both target `/events` in embedded mode, and the viewer loads the iframe with `#/events`. Standalone behavior unchanged: `/` still goes to `/files`.)** Works identically in standalone and embedded mode; no embed-shim changes needed (the shim only gates `/files` and backend fallbacks).
- **Left pane columns:** **#** (sequence number = index into the connection's event array — qlog events have no intrinsic ID, the array index is the honest, stable identifier), **time** (relative ms from capture start, from `parseEvent(evt).relativeTime`, fixed 3-decimal formatting), **event type** (canonical spec-final `category:name` — free via the existing `normalizeEventPair` load path), **summary** (per-type formatter).
- **Summary formatters** (module of pure functions, one per common event type + generic fallback): packet events → packet type, packet number, frame-type roll-up (e.g. `1RTT #1234 · STREAM(0, 12000B), ACK`); STREAM-frame-level and `stream_data_moved` events → stream id, offset, length, fin; `http3:frame_created/frame_parsed` HEADERS → method+path / status, DATA → byte length; `recovery_metrics_updated` → changed-metric `k=v` pairs; `connectivity:*` → state/addresses; `parameters_set` → ALPN/cipher/owner. Fallback: first N scalar keys of `data` as `k=v`. Formatters must tolerate missing/malformed fields (return partial or empty summary, never throw).
- **Stream association is multi-valued.** HTTP/3-level events carry `data.stream_id` directly; transport-level stream activity is nested in `data.frames[].stream_id` inside packet events. An event's stream set = direct `stream_id` ∪ all frame `stream_id`s; a packet carrying frames for three streams appears in all three streams' context views.
- **Non-reactive index (stats-tab lesson — hard requirement).** Per connection, build once on first Events-tab use: a plain array of `{seq, relMs, category, name, typeStr, summary, searchStr, streamIds}` plus a `Map<streamId, seq[]>` stream index. Stored OUTSIDE Vue reactivity (module-level `WeakMap<Connection, index>`); components consume it via `shallowRef`/computed over plain arrays. Raw events and index rows must never become reactive proxies; template expressions stay render-pure (no lazy table builds or cache resets in lifecycle hooks — that exact pattern caused the stats-tab recursive-update tab lock).
- **Virtualization is mandatory, hand-rolled, fixed row height.** Real captures run to 10⁵+ events; a naive `v-for` locks the tab. Both the left event list and the right stream-context list use a small local fixed-row-height windowed-rendering component (~100 lines, no new dependencies — keeps the fork upstreamable and honors the license policy). Filtering runs as a plain array pass over precomputed lowercase `searchStr` (type + summary), debounced ~150 ms; only rendering is windowed.
- **Right pane layout:** top section = selected-event details (pretty-printed raw event JSON, text interpolation only — qlog field values are attacker-controlled, the tree stays `v-html`-free); bottom section = stream context. When the selected event is associated with exactly one stream, show that stream; with several, a small stream picker (tabs/pills); with none, details only.
- **Stream-context rendering (Pat, 2026-07-05):** qlog events are flat points in time — no netlog-style begin/end nesting — so the context list is flat and time-ordered. Each event is clearly separated from its neighbors: every item starts with a visually distinct separator row carrying `#<seq>` and `+<relMs> ms` (relative to capture start), followed by the event's type and summary lines. The selected event is highlighted and auto-scrolled into view; clicking any context item re-selects it (updating details and, where visible under the active filter, the left-list highlight). Fixed per-item block height so virtualization stays simple.
- **Filter bar:** case-insensitive substring input + category dropdown (populated from categories present in the connection). Fancier query syntax is out of scope.
- **Connection selection:** reuse `ConnectionConfigurator` with single-connection selection, mirroring the packetization/multiplexing tabs (one qlog file = one connection; multi-file loads need the picker).
- **Future hook (non-goal now):** deep-linking from an event into the sequence diagram at its timestamp.
